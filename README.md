# expertbook-tweaks

Personal tweaks for an ASUS ExpertBook Ultra (B9406CAA) running Omarchy, on top
of the community fixes in [asus-expertbook-linux](https://github.com/burakgon/asus-expertbook-linux),
used unmodified from upstream `main`.

Files here are the real copies; `./install.sh` symlinks them into place, so
editing either path edits the tracked file. `./install.sh --system` also copies
`system/` into `/` via pkexec (those can't be symlinks into a home directory).

## What's here

| Path | Linked to | Purpose |
|---|---|---|
| `hypr/hdr.lua` | loaded by `~/.config/hypr/monitors.lua` | Internal OLED in always-on HDR, 10-bit (`edp_hdr_monitor()`), border dimming; software cursor, because the hardware cursor plane skips colour management and renders at peak brightness in HDR. `monitors.lua` itself stays a real file because Omarchy edits its scale lines with `sed -i`, which would replace a symlink. |
| `hypr/input.lua` | `~/.config/hypr/` | Caps Lock is Ctrl (`ctrl:nocaps`; the keyboard has no Right Ctrl), no Compose key; both Shifts toggle Caps Lock. Natural touchpad scrolling. |
| `hypr/bindings.lua` | `~/.config/hypr/` | Brightness keys (plain/Alt) call `hdr-brightness`; Shift + them calls `white-point`. F14 (code:192) is deliberately unbound: the ASUS firmware sends it on every USB-C power plug/unplug (asus_wmi 0x77), not just Fn+F9. |
| `hypr/hypridle.conf` | `~/.config/hypr/` | Display off after 8 min idle, suspend (Omarchy locks on suspend) at 10 min; both skipped in Omarchy stay-awake. On wake from suspend, `bin/brightness-wake-floor` raises the screen to at least 5% so the lock screen is visible. Needs `pacman -S hypridle`. Omarchy shell.json (not in repo) has `idle.screensaver = 0`, `idle.lock = 0`. |
| `bin/hdr-brightness` | `~/.local/bin/` | In HDR the panel ignores its backlight, so brightness is Hyprland's `sdrbrightness`, saved to `~/.local/state/hdr-brightness` and reapplied by `monitors.lua`. HDR off or another monitor: passes through to `omarchy-brightness-display`. No step prints the current percent. |
| `bin/ambient-display`, `systemd-user/ambient-display.service`, `bin/white-point` | `~/.local/bin/`, `~/.config/systemd/user/` | Ambient-light brightness **and** white point in one daemon (replaced `hdr-auto-brightness` and `ambient-white`, 2026-11-06). One sensor thread reads lux ~1 Hz and colour every third read (each ISH read blocks ~1 s). Both controllers work the same way: a model predicts from the sensors, the screen glides there calmly, and manual changes are learned once left alone for 4 s. **Brightness** (through `hdr-brightness`, works in HDR): learned monotonic lux→nits points on log lux (nits so the curve survives changing `edp_sdr_white`, published by `hdr.lua` to `~/.local/state/hdr-sdr-white`); lux smoothed 7.5 s up / 30 s down, 3% deadband, 1% steps every 0.7 s up / 1 s down; never auto-sets below 5% (below that, including 0, is manual-only and never learned). **White point** (through hyprsunset, 100 K grid): lit → partway (35% in mireds) toward the room's colour, 5000–6600 K; dark (the sensor's fixed 4500 K "can't measure" reading for 15 s, colour lost around 7–37 lux) → fades on log lux from the last lit value at the lux where colour was lost to 4500 K at ≤ 3 lux; plus learned corrections. Shift + brightness keys run `white-point` (dim = warmer, bright = cooler, 200 K, 2500–6600 K, OSD), which sets hyprsunset and writes `~/.local/state/white-point.manual`; the daemon holds it and learns the difference from the model (mireds) at the room's lux. Corrections interpolate on log lux and fade back to the plain model over a decade past the outermost points, and are kept separately for day and night, blended by the sun's elevation through civil twilight (±6°; location from wttr.in's IP lookup, cached; where one has nothing near the current lux it borrows the other's), so a dark room can learn different preferences by day and by night. Calm movement: room colour smoothed over 90 s (lux 30 s); the screen holds still until the target is 150 K away, then glides all the way there in 20 K steps (hyprsunset takes any kelvin; 100 K steps read as a series of jumps) at ≤ 0.8 mired/s, so a dark↔lit swing takes ~90 s and a typical room change a few minutes. 6600 K is hyprsunset's ~identity. Re-sends every 30 s (hyprsunset re-applies its profile daily). State: `~/.local/state/ambient-display.json` (`brightness`, `white_offsets`, `dark_fade`; delete a key to forget it). SIGUSR1 = adopt the current brightness without learning it. Logs: `journalctl --user -u ambient-display`. |
| `bin/brightness-wake-floor` | `~/.local/bin/` | Called by `hypridle.conf` on wake: if brightness is below 5% (`FLOOR`), sets 5% and sends `ambient-display` SIGUSR1 so it adopts the new level without learning it, then fades to its usual level for the room. |
| `fontconfig/60-grayscale-antialias.conf`, `hl.env("QSG_DISTANCEFIELD_ANTIALIASING", "gray")` in `hypr/hdr.lua` | `~/.config/fontconfig/conf.d/` | Greyscale text antialiasing instead of subpixel. The Omarchy 4.5 bar draws text and icons on a transparent layer, where subpixel AA's per-channel coverage ends up with RGB above the single alpha (correct would be alpha = max channel coverage). Blending that overshoots 1.0: clamped invisibly in an 8-bit (unorm8) SDR buffer, but kept in Hyprland's higher-precision HDR blending and shown brighter than white (stray bright pixels on icon edges). Qt Quick ignores fontconfig here, hence the env var as well. |
| `hypr/hyprsunset.conf` | `~/.config/hypr/` | Neutral startup profile for hyprsunset; `ambient-display` drives it. (A sunset/sunrise schedule preceded it: git history `nightlight-sun`.) |
| `omarchy-plugins/mtklein.nightlight/`, `omarchy/omarchy-menu.jsonc` | `~/.config/omarchy/plugins/`, `~/.config/omarchy/extensions/` | Night light toggle for `ambient-display`: a clone of Omarchy's night light service (`omarchy plugin clone omarchy.nightlight`) with 4500 K on / 6600 K off, "on" meaning below 5000 K (not Omarchy's 6000, since lit rooms go down to 5000 K), a 30 s re-read so the bar follows the daemon, and a toggle that writes `~/.local/state/ambient-white.override` (`night`/`day`), honoured until the room next changes dark ↔ lit or the white point keys are used. The menu file points Trigger > Toggle > Nightlight at the service. `omarchy toggle nightlight` on the command line bypasses all this (4000 K). |
| `omarchy-themes/tiger/` | `~/.config/omarchy/themes/tiger` | **Tiger**: Mac OS X 10.4 as a light Omarchy theme (`omarchy theme set tiger`). White, near-black and neutral greys; Aqua blue (`#3875d7`) for focus and selection, Tiger's `#b5d5ff` text selection; stoplight hues for red/yellow/green, deepened so every colour reads as text on white (normal ≥ 4.5:1, bright ≥ 3.4:1). `foot.ini` replaces the generated one, whose template uses the background as ANSI black (invisible black text on a light theme). `hyprland.lua`: glossy Aqua gradient on the focused window's border, grey on the rest, soft Aqua-style drop shadows (border variable names kept for `hdr.lua`'s dimming). Icons Yaru-blue. `shell.bar.toml` (Omarchy merges a theme's `shell.<section>.toml` over that section of the generated shell styling) makes the bar OLED black with light-grey text and stoplight-red alerts, while popups stay light; the bar sits at the bottom, opaque (`omarchy bar position bottom`, `omarchy bar background opaque`). `shell.menu.toml` and `shell.launcher.toml` set the menu's and launcher's `scrim-alpha` to 0: light themes otherwise wash the whole screen in 50% white behind the card. `shell.polkit.toml` gives the password prompt a real dim instead (Tiger near-black at 45%). `shell.popups.toml`, `shell.tooltip.toml` and `shell.controls.toml` make the bar's panels (Wi-Fi, Bluetooth, battery, calendar…), tooltips and OSDs dark (`#161618`, light-grey text and control chrome): Omarchy draws panel text in the bar's own text colour (`bar.foreground`), so with the black bar's light-grey text, white panels were unreadable. Chromium keeps the generated white seed (a `#d4d4d4` Tiger-grey seed was tried and dropped: its grey/white mix didn't read well). The wallpaper (the 10.4 Aqua swoosh, 6016×3760 from 512pixels.net) is Apple's artwork, so it's gitignored and `install.sh` fetches it, plus the theme picker's preview. |
| `omarchy-plugins/mtklein.workspaces/`, `mtklein.active-window/`, `mtklein.clock/`, `mtklein.tray/`, `omarchy/bar-layout.json` | `~/.config/omarchy/plugins/` | A Mac-style menu bar (clones of Omarchy's widgets). Left: desktop numbers for occupied desktops only, plus the one on screen (like Super+Tab; the current one bright, the others dim; no layout glyph), then the focused app's name in bold Luxi Sans (from its desktop entry; the window title is the tooltip), then `omarchy.indicators`. Tray: every app icon (Steam, …) always on the bar, no `<` drawer unless you hide an icon or put widgets in the tray section; picking up a newly cloned widget needed `omarchy restart shell`. Right: status icons, world time, the clock in Luxi Sans as `ddd h:mm AP` (Tiger's "Sat 1:04 PM"), weather in the corner. The indicators' hover-reveal opens while the pointer is left of where the centre box starts, so they must sit in the left section to appear near the pointer. `bar-layout.json` is a snapshot of `shell.json`'s bar layout (which isn't in the repo); merge it back with `jq -s '.[0] * .[1]' ~/.config/omarchy/shell.json omarchy/bar-layout.json`. Bar background (clear/glassy/opaque) is left to taste: double-click the bar to cycle. |
| `fontconfig/61-tiger-sans.conf` | `~/.config/fontconfig/conf.d/` | Luxi Sans (AUR `ttf-luxi`, Bigelow & Holmes' free sibling of Lucida Grande) as the default sans-serif. Matches only requests whose *first* family is Liberation Sans: Omarchy's `50-omarchy.conf` has already rewritten `sans-serif` to it, and every pattern carries generic fallbacks, so matching any position hijacked named fonts (foot got Luxi instead of its monospace font). Monospace is DejaVu Sans Mono via `omarchy font set "DejaVuSansM Nerd Font"` (the Nerd variant keeps the bar's icons). |
| `bin/workspace-layout-toggle` | `~/.local/bin/` | Omarchy's workspace layout cycle (tiling → scrolling → floating) without the notification it posts on every change: an exported bash function shadows `omarchy-notification-send` for the child script. Super+L / Super+Alt+L (`hypr/bindings.lua`) and clicking the current desktop number (`mtklein.workspaces`) use it. |
| `omarchy-plugins/mtklein.osd/` | `~/.config/omarchy/plugins/` | Omarchy's on-screen display minus the app launcher's "Launching <app>…" box (shown when a window takes over 2 s, e.g. Steam), recognised by its icon (U+F14DE); volume, brightness and white point OSDs are unchanged. Instead it raises `$XDG_RUNTIME_DIR/omarchy-launching` (cleared when the launcher closes the box: window up, or its 15 s timeout), which `mtklein.active-window` shows as a Tiger-style 12-spoke spinner after the app name (20 s safety timeout; static with animations off). The launcher is core shell code, the OSD a clonable plugin. Like the other clones, it took `omarchy restart shell` to load. |
| `hypr/super-console.lua` | loaded by `hypr/bindings.lua` | A tap of Super on its own (released within 300 ms, no other key) toggles Omarchy's Quake console (`special:qconsole`, also Super+\`). Longer presses and chords do nothing, so pausing on Super before a shortcut never toggles it. (A hold-to-peek mode existed briefly; removed 2026-11-08.) Built on Hyprland's Lua `input.keyboard.key(keycode, ?, state)` event and a one-shot `hl.timer` (Super = evdev 125/126 or xkb 133/134). |
| `bin/sdw-clash-recover`, `systemd-user/sdw-clash-recover.service` | `~/.local/bin/`, `~/.config/systemd/user/` | Brings the bass back after a SoundWire glitch. The CS35L56 woofer amps are on link 2; a sporadic "Bus clash" / "Parity error" there (a few a day, seen mid-playback with nothing else happening) can leave them silent while the tweeters keep playing. The kernel's Cadence driver only logs these and never resyncs, so this follows the kernel log and suspends/resumes the speaker sink, which re-prepares the stream (sub-second blip). Recoveries: `journalctl --user -u sdw-clash-recover`. |
| `bin/game-touchpad-guard`, `systemd-user/game-touchpad-guard.service` | `~/.local/bin/`, `~/.config/systemd/user/` | Turns the touchpad off (silently, not persisted) while a game in its `GAMES` list (window class or title; FF Resonance for now) is focused, and back on when focus leaves, so stray touches don't wake the mouse cursor. A touchpad turned off with `omarchy-toggle-touchpad` stays off. Follows Hyprland's event socket. |
| `bin/hdr-monitor-state` | `~/.local/bin/` | `omarchy-monitor-state` with the brightness line from `hdr-brightness`. |
| `omarchy-plugins/mtklein.monitor/` | `~/.config/omarchy/plugins/` | Clone of the bar's Display panel; `Panel.qml` reads/sets brightness through the two scripts above. Doesn't receive upstream `omarchy.monitor` updates. |
| `fingerprint/omarchy-hw-fingerprint` | `~/.local/share/fp-shim/` | Detection shim: Omarchy misses the FocalTech FT9349 (`2808:a97a`), which libfprint supports. Run setup as `PATH=~/.local/share/fp-shim:$PATH omarchy-setup-security-fingerprint`. |
| `fingerprint/fp-storage.py` | `~/.local/share/fp-shim/` | List (`sudo python3 fp-storage.py`) or wipe (`--clear`) templates stored on the sensor chip. Stale Windows Hello templates there made every verify fail. |
| `wluma/config.toml` | `~/.config/wluma/` | Ambient-light screen brightness, keyboard excluded. **Unused** (wluma isn't installed): it drives the backlight, which does nothing in HDR; `ambient-display` replaces it. |
| `system/usr/local/bin/rapl-sync`, `system/etc/systemd/system/rapl-sync.service` | `/usr/local/bin/`, `/etc/systemd/system/` | Copies the firmware's (MMIO) PL1/PL2 onto the MSR RAPL limits every 2 s, as Windows does. The BIOS leaves MSR PL1 at 15 W and the CPU obeys the lower copy, so without this every profile sustains only 15 W. |
| `system/etc/systemd/system/ollama.service.d/override.conf` | `/etc/systemd/system/ollama.service.d/` | Ollama on the Arc B390 iGPU, flash attention, q8_0 KV cache, 32k context. |
| `system/etc/udev/hwdb.d/70-pocketpad.hwdb` | `/etc/udev/hwdb.d/` | Button names for [PocketPad](https://github.com/Dathaze20/PocketPad), the Android app that makes the Retroid Pocket Nova a Bluetooth HID gamepad (`0005:001D:1200`, "RPN"). It declares 16 anonymous buttons, so the kernel names them in order and SDL's automatic mapping (Steam, native games) put X/Y, bumpers, Select/Start and stick clicks on the wrong functions; this renames them to the standard codes. Android keeps Home for itself. Connect from the Nova (PocketPad → Settings → Connect to a paired device). |
| `system/etc/modules-load.d/uinput.conf` | `/etc/modules-load.d/` | Loads `uinput` at boot. steam-devices grants `/dev/uinput` access (uaccess) only once the module is loaded; without it Steam Input can't create virtual controllers, so Proton games get no input from controllers Steam itself reads fine. |

## Known quirks

- `sdrbrightness` doesn't reach window borders, so `monitors.lua` dims the theme's border colours by the same factor (linear light), re-reading the theme each time.

## Tools

- `tools/power-profile-loadtest.sh`: 60 s all-core load in each power profile, reporting package power. Run on AC and on battery to compare (`pkexec bash tools/power-profile-loadtest.sh`).
- `tools/power-trace.sh`: 50 s load in Performance, printing power, temperature and PL1 every 5 s.
